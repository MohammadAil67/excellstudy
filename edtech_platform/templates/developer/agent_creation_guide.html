Creating an Agent

Everything you need to know about building a compliant AI teaching agent for the ExcellStudy platform — from architecture to field constraints.

Spec v2.0 ~15 min read Platform compliant
01 — Overview

What is an ExcellStudy Agent?

An ExcellStudy Agent is a containerised AI service that receives a learner input, processes it using your model or logic, and returns a structured educational response. Every agent runs in isolation, communicates exclusively through our defined API contract, and must pass the automated pipeline before going live.

Agents are subject-matter specialists — a single agent should focus on one domain (e.g., Algebra, Chemistry, Essay Writing). Multi-subject generalist agents are not accepted.

Platform Note Your agent must be registered on the portal before you push its Docker image. The pipeline cross-validates the pushed image against the registration metadata.
02 — Architecture

How Agents Work

Your agent is a stateless HTTP service inside a Docker container. The platform calls it on each learner interaction.

Docker Container
Your agent must be packaged as a Docker image and pushed to the ExcellStudy registry.
REST API Contract
Your container must expose a POST /infer endpoint that accepts our payload schema.
Stateless Design
Each request is independent. Do not persist learner data inside your container.
manifest.json
A metadata file bundled with your image that describes your agent's capabilities and constraints.
03 — Manifest

manifest.json

Every agent image must include a manifest.json at its root. This file is read by the pipeline during the schema validation step. Any mismatch with your portal registration will cause the pipeline to fail.

// manifest.json — place at the root of your Docker image { "name": "My Math Agent", "version": "1.0.0", "description": "Teaches algebra fundamentals for ages 10–16", "entry_point": "main:app", "port": 8080, // Must match the input_type chosen during registration "input_type": "text", // Must match output_types chosen during registration "output_types": ["text", "hint"], // At least one subject area required "subject_areas": ["algebra", "mathematics"], // Age range your agent is designed for "age_groups": ["10-13", "14-16"], // Optional feature flags "capabilities": ["step_by_step", "adaptive_hints"] }
Fields must match your portal registration exactly. If input_type or output_types in your manifest differ from what you registered, the pipeline's schema validation step will immediately fail.
03a — Fields Reference

manifest.json Field Reference

Field Type Status Description
name string Required Human-readable agent name. Must match portal registration.
version string Required Semver format e.g. 1.0.0. Must match portal registration.
description string Required Short description of what the agent teaches. Max 300 chars.
entry_point string Required Python module path to your ASGI/WSGI app e.g. main:app.
port integer Required Port your container listens on. Must be 8080.
input_type string Required One of the approved input types. Must match registration.
output_types array Required List of approved output types. Must match registration.
subject_areas array Required At least one subject area. Must match registration.
age_groups array Required Target age ranges e.g. ["10-13", "14-16"].
capabilities array Optional Feature flags like step_by_step, adaptive_hints.
04 — I/O Types

Approved Input & Output Types

Only the following types are accepted by the platform. You must select from this list when registering and in your manifest.

Input Types
  • text — Plain text question
  • image — Photo or diagram upload
  • audio — Voice recording
  • code — Code snippet
  • math_expression — LaTeX / MathML
  • multiple_choice — MCQ with options
  • structured_data — JSON payload
Output Types
  • text — Plain text response
  • hint — Scaffolded hint
  • score — Numeric evaluation
  • explanation — Step-by-step breakdown
  • feedback — Qualitative feedback
05 — Constraints

Platform Constraints & Rules

All agents are reviewed against the following requirements. Violating any of these will result in automatic rejection during the pipeline or during manual review.

Allowed — Your agent must do all of these
  • Respond within 5 seconds per request
  • Return well-formed JSON matching the output schema
  • Return HTTP 200 on success, 4xx/5xx on errors
  • Focus on one subject area per agent
  • Produce age-appropriate, curriculum-aligned responses
  • Run on port 8080 inside the container
Blocked — These will cause automatic rejection
  • Storing or logging learner PII (name, email, chat history)
  • Making outbound network calls to third-party APIs during inference
  • Writing to the filesystem during a request
  • Responses that generate off-topic, harmful, or age-inappropriate content
  • Container images larger than 4 GB
  • Running as root inside the container
